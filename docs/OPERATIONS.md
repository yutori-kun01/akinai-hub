# 運用・更新・復旧

## 日常確認

設定画面の最終自動処理結果、配信履歴の失敗、銀行振込の入金待ちを確認。手動の入金確認は実際の入金照合後に実行します。「利用停止」はアクセス権を停止する操作で、返金処理ではありません。返金は決済会社で別途行ってください。

## バックアップ

設定画面で「今すぐ保存」。管理レコード・配信ジョブ・抑止リストのJSONと、現在の商品に関連付く納品ファイルのコピーをR2へ保存します。ログイン情報やAPIキーは含めません。R2やCloudflareアカウント全体の消失には同一アカウント内のコピーだけでは備えられません。

管理データJSONをダウンロードし、以下で対応するファイルを外部保管します。保存先フォルダは新規の名前を使ってください。

```sh
node scripts/release/backup-files.mjs commerce-backup.json ./backup-2026-10-14
```

出力されたフォルダ全体を暗号化して別の保管場所へ保存します。メールアドレス・商品データなどを含むので、販売用ZIP・公開Git・サポート投稿には入れないでください。

## 復元

同一店舗ID・同じR2なら、管理画面でJSONを選択 → 復元内容を確認 → RESTOREと入力。現在の状態も先にバックアップしてから置き換えます。未送信・処理中のメールはキャンセルに変わります。キャンペーンとステップの状態も確認し、必要なら停止してください。復元前にMAIL_ENABLED=falseへ切り替えることを推奨します。

R2も失われた場合は、新しいD1/R2と同じWORKSPACE_IDを用意して導入をやり直します。シークレットと管理者を再設定した後、外部保管ファイルを戻します。

```sh
node scripts/release/restore-files.mjs ./backup-2026-10-14 --restore-files
```

その後に同フォルダのmanifest.jsonを管理画面で復元します。購入者は同じメールアドレスで再ログインできます。管理者アカウントは別途再作成します。Stripeの決済履歴と突き合わせ、バックアップ後の購入を手動確認してください。

バックアップ上限: 管理レコード1万件、配信ジョブ3万件、現在の商品に関連付くファイル1千個。超える場合はD1/R2の直接バックアップが必要です。アップロード上限は1ファイル25MB。未使用ファイル・全操作履歴・外部動画本体はアプリバックアップの対象外です。

## 更新

1. MAIL_ENABLED=false、COMMERCE_ENABLED=falseにして一時停止。
2. バックアップを作り、外部にも保存。
3. 新しいZIPを別フォルダに展開。自分のwrangler.standalone.jsonだけをコピー。古いソースやnode_modulesを混ぜない。
4. pnpm install --frozen-lockfile。
5. 追加DB移行を適用。既存のmigrationファイルを変更しない。
6. ビルド・デプロイ。新しい環境にしない限りCloudflare上のシークレットは維持。
7. ログイン・購入履歴・ファイル取得・配信停止を確認して再開。

旧Worker版へのロールバックだけではDBは戻りません。DB変更との互換性をリリースノートで確認してください。重大障害は停止状態を保ち、復元手順を使います。

## 管理者パスワードの復旧

メールが使える場合は管理者メールアドレスでコードログイン可能です。パスワード自体を再設定する場合は、Cloudflareアカウントで認証された管理者が次の順に実行します。

1. 新しいSETUP_TOKENをCloudflareシークレットに設定。
2. D1コンソールで `DELETE FROM auth_admin WHERE id=1;` と `DELETE FROM auth_sessions;` を実行（既存のログインをすべて無効化）。
3. /setupで同じADMIN_EMAILと新しいパスワードを設定。
4. SETUP_TOKENを削除。

メールやチャットにパスワード・APIキーを送らないでください。
